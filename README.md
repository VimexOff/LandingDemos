# Демо-лендинги

Два лендинга для вымышленных компаний, сделанные как примеры работ. Чистые HTML, CSS и JavaScript, без фреймворков и библиотек.

## Демо

- [Оглавление](https://vimexoff.github.io/LandingDemos/)
- [Клининг «Пеночка»](https://vimexoff.github.io/LandingDemos/landing-cleaning/)
- [Парикмахерская «Цирюльня на Кузнечной»](https://vimexoff.github.io/LandingDemos/landing-barbershop/)

## Клининг «Пеночка»

![Первый экран «Пеночки» на компьютере и калькулятор на телефоне](screenshots/cleaning.png)

Главное здесь калькулятор: площадь, тип уборки и допуслуги, цена пересчитывается сразу. Кнопка «Заказать уборку» переносит расчёт в комментарий заявки, чтобы клиенту не пришлось повторять его по телефону. Ещё есть FAQ-аккордеон и форма с проверкой имени и телефона.

Как устроено в коде ([`landing-cleaning/script.js`](landing-cleaning/script.js)):

- ставки за метр и цены допуслуг лежат в `data-` атрибутах полей, поэтому прайс меняется в HTML без правки скрипта;
- расчёт отделён от вывода: одна функция считает сумму, другая рисует детализацию, а итог округляется до 50 ₽;
- на телефоне внизу калькулятора закреплена строка с итогом, чтобы цена была видна, пока выбираешь опции.

## Парикмахерская «Цирюльня на Кузнечной»

![Вывеска и журнал записи «Цирюльни»](screenshots/barbershop.png)

Первый экран сделан в виде вывески. Запись идёт через журнал на неделю: мастера по колонкам, занятое время подписано именами клиентов. Клик по свободной клетке подставляет день, время и мастера в форму, а после отправки ваше имя появляется в журнале. Форма учитывает график мастеров и не даст записаться к тому, у кого выходной.

Как устроено в коде ([`landing-barbershop/script.js`](landing-barbershop/script.js)):

- график мастеров читается из разметки (`data-days` у карточки мастера), отдельного списка в JS нет;
- журнал и форма работают с одним объектом расписания, поэтому время, занятое в журнале, недоступно и в форме;
- занятость условная, но стабильная: она считается по хешу от даты, времени и мастера, так что при перезагрузке журнал не меняется;
- даты собираются из локального времени, а не через `toISOString()`, иначе вечером по Москве «сегодня» превращалось бы во «вчера».

## Технически

- вёрстка mobile-first, проверял на ширине 360, 768 и 1280 px;
- меню, аккордеон и формы доступны с клавиатуры, у интерактивных элементов есть aria-атрибуты;
- анимации отключаются, если в системе включено уменьшение движения;
- шрифты системные, картинки нарисованы на SVG, внешних запросов нет;
- формы работают только в браузере и никуда не отправляют данные.

## Что можно доработать

- отправлять заявки на сервер или в Telegram-бота;
- форматировать телефон прямо во время ввода, сейчас это происходит при выходе из поля;
- заменить SVG-иллюстрации настоящими фотографиями;
- брать расписание парикмахерской с сервера, а не считать занятость в браузере.

## Запуск

Сборка не нужна, достаточно открыть `index.html` в браузере.
